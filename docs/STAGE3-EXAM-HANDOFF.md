## 服务器核验与访问

上传前确认：服务器 `/home/ubuntu` 所在文件系统约 59 GB，剩余约 51 GB；目标目录此前不存在。上传完成后远端目录统计为 **22 个文件**（21 个音频 + `manifest.json`），目录占用 **789,374,839 bytes**（含清单）。

登录服务器后由 `ubuntu` 用户核验：

```bash
ls -lah /home/ubuntu/stage3-audio-v1
cat /home/ubuntu/stage3-audio-v1/manifest.json
find /home/ubuntu/stage3-audio-v1 -maxdepth 1 -type f \( -iname '*.mp3' -o -iname '*.wma' \) | wc -l
```

要让考试应用提供播放，后续需先确定应用服务账号和媒体分发方式，再由 Stage 3 实现媒体映射、Range 请求、音频格式兼容及鉴权/静态访问策略。当前目录是私有暂存资产，Nginx 或 Node 服务不能直接读取/公开它；不要在没有设计确认的情况下把它改为 world-readable 或直接放到站点公开目录。服务若需读取，可在后续部署步骤中通过受控权限/复制或挂载接入。

## 接手线程建议先做的事

1. `git switch stage-3-exam` 并从 `github` remote 快进拉取分支；本交接文档所在提交合入后，以最新分支状态为准。
2. 先读 `AGENTS.md`、本交接文档，以及 `docs/软柿子开发清单.md` 的“阶段 3：30–45 分钟短测试”部分。D23–D30 为 Stage 3 范围，D23–D24负责正式题库/整卷与考试实例衔接。
3. 将服务器私有音频目录视为只读源资产。用 `manifest.json` 验证需要的场次和格式；不要提交约 789 MB 音频到 Git。
4. 先设计并实现题目版本到音频文件的稳定映射，再处理服务进程访问权限与媒体路由。注意 2015、2016、2024 为 WMA；现代浏览器 `<audio>` 对 WMA 的支持有限，是否转码应作为单独决策，不能假定原件可直接播放。
5. 实施 D27/D30 时覆盖 21 个场次映射、MP3/WMA兼容方案、移动端播放、暂停/重播、材料计时和 HTTP Range（206）/断点续传检查；仅“服务器上存在文件”不构成 D27/D30 完成证据。
6. 保留当前已有考试快照、历史存档和报告，不用 Stage 3 改写它们；新题库内容仅影响之后创建的考试。部署仍按清单中的阶段验收流程推进，不因本次上传自动发布。
