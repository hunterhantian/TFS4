# Stage2机器主导题库生产流程

版本：1.6。日期：2026-10-27。依据：用户明确授权助手执行最佳质量OCR、全部校对、修订整理和JSON存储；系统审核简化为确认步骤。本文是产品规划、技术路线和开发清单1.6共同引用的执行规范。

**本轮仅修改设计和开发安排，不运行新的OCR、校对入库或全题库批处理。** 本文中的新增能力均待实现与验证，不以文档更新冒充已经完成。

## 1. 核心链路和职责

**资料登记与分年分卷 → 强制最佳质量OCR → 助手全量对照原页校对并修订 → 保存可追溯JSON → 程序质量校验 → 机器校对通过的内容入库 → 可选整批确认/退回 → 独立AI关联维护。**

| 参与方 | 负责事项 |
| --- | --- |
| 助手/AI | 检查资料、拆分混合年份、强制OCR、逐页逐题校对、修改整理、JSON与修订记录、结构和材料校验、本机批次处理、分类与关联尝试、测试和文档 |
| 用户 | 提供已有资料；可选择整批确认、退回或查看异常；完成阶段体验验收。无需重新做OCR、逐字校对、逐题分类或建立关联 |
| 程序 | 执行可复算的题号、选项、材料、答案映射、哈希、版本、去重、权限和事务检查，保留阶段状态和处理证据 |

用户授权助手修订整理，常规OCR错误和排版修复不逐项请求批准。校对责任由机器承担；质量由对照记录和程序验证证明，不宣称AI不会犯错。机器校对通过与人工确认分别记录，不能把AI操作伪装成人工审核。

## 2. 所有文档强制最佳质量OCR

- 覆盖每份待录入试卷、答案、解析和听力原文，包含已有OCR文字层、可搜索PDF、原生文字PDF及用户先前处理的版本；不再有“能复制文字就跳过”的分支。音频本身不是OCR对象，单独登记、核对和挂接。
- 原始文件只读保留，登记SHA256、文件名、角色、实际年份、卷别、页数及重复关系。多年份合并PDF先按原页确认并分卷，保留父文件哈希及页码映射；不得按文件名猜年份。例如111.pdf的前25页2024、后20页2023须分别处理，不能整份标2023。
- **不能把NAPS2对已有文字层的默认跳过识别当作重做OCR。** 实施时先将本次来源全部页面渲染为保留版面的无文字层图像，再用明确生效的Best/最佳质量配置重新识别。原文字层只作差异比较，不作为替代输入。
- 默认按300dpi渲染，保持页面尺寸、方向、完整边缘及页序；小字/模糊页可提升渲染分辨率或重做，记录参数，不声称放大能恢复原图没有的信息。不使用可能删掉负号、重音或标点的激进去噪。
- 主要语言为法语，按内容加入简体中文；混合语言策略先在最小测试中验证，记录实际选择及语言模型文件哈希。不能只凭语言包已下载就认定任务使用了它。
- 必须保存工具/引擎版本、实际模式、语言、模型、渲染DPI、输入与输出哈希、页数和运行结果。以 installed help/config 为依据实现可重复调用，不能虚构CLI参数；`--force`覆盖文件不等于强制识别，`--ocrlang fra`不证明Best模式。
- 同一来源即使重复入队也要执行规定的强制OCR；内容去重与幂等控制发生在之后的JSON/数据库阶段，不得用导入去重绕过本次OCR要求。

## 3. 助手全量校对、修改整理后才保存正式内容JSON

1. 对OCR覆盖范围内每一页执行一次原图与识别文字的对照；题目范围内逐题检查题号、题干、A/B/C/D选项、答案来源映射、Part/题型与材料归属。检查阅读文章、完形全文、听力原文、跨页续接、标题与所有材料题组，不仅抽查题干。
2. 修复重音、连字、标点、OCR错字、题号如S1/51、选项粘连/串入后题、水印噪声、漏字、错误换行及填空位置。下划线不能因为OCR没识别就直接丢弃，也不能凭语感任意加在未知位置。
3. 区分“原图是什么”和“AI建议怎么修正”。按清晰原图纠正录入无需用户重复批准；原始资料本身疑似有误时保留原文与建议、理由和状态，不无痕改写。每项有效修订保留题号/材料/页码、修改前后和依据；记录覆盖到哪一页哪一题，未做完不填“全量完成”。
4. 校对完成后生成整理JSON，保留稳定的来源/题目/材料ID、版本、原题号和原顺序。不能仅把原始OCR文字保存成JSON就称已校对。
5. 对低清、遮挡、缺页、答案/解析矛盾再做定向核查。仍不确定时标记到具体题目或材料，其他已完成内容继续，不把整批普通校对工作退给用户。必要缺失资料集中汇总。

所有OCR文档都需要校对，包括答案和解析；不能只校对试卷而默认专家答案或解析必然正确。无法识别或未校对部分明确未完成，不为凑题量或通过率补造内容。

## 4. 答案与依据的处理

- 用户指定参考答案继续作为判分基准；2025的61=A、62=B保持，所有历史快照和成绩不重算。
- 允许助手根据明确原页修复OCR/映射错误并留痕，无需逐题请用户确认。答案与解析冲突要单列原值、证据、分析和处理状态，不通过改答案来掩盖冲突。
- 缺参考答案、缺解析、来源出处不明分别记录。AI可以提出建议答案/分析，但必须标为AI建议，不能冒充原文、官方答案或官方解析。题面草稿整理和非正式匹配试验可继续；没有明确可采用判分依据的题目不能混入正式自动判分。
- 官方出处未核实不再等同于“必须用户在后台手动点确认”。助手核对本地资料及证据，记录可核实的出处范围；确实无依据的内容保持相应状态。关联可分“有解析依据”和“基于题面推断”，后者仅作实验候选。

## 5. JSON、存档与状态设计

原始PDF、强制OCR结果、原始OCR文字、修订JSON、导入JSON和数据库是不同层，分别保存并以哈希关联。原始资料、生成PDF及凭据在私有/忽略目录，运行证据和去隐私清单可进入Git。

拟新增处理清单JSON（当前接口尚未接受这些元数据，需实现后验证）：

| 记录 | 必要内容 |
| --- | --- |
| batch.manifest.json | 批次ID、来源/分卷/页码映射、各阶段状态、输入输出哈希、失败/重试及覆盖范围 |
| ocr.run.json | 强制重新识别的证明、Best模式、语言/模型/工具版本、DPI、全部页结果与可搜索PDF路径 |
| raw-ocr.json | 原始逐页文字，原样保留作为差异来源，不标成已校对 |
| proofread.json | 校对后的题目/材料/答案/解析、逐页逐题覆盖、修订列表、问题与来源位置、执行者AI及时间/版本 |
| import-v2.json | 与现有schemaVersion=2兼容的导入对象；不能携带未知字段绕过现有校验 |
| association-experiment.json | 跨年份候选对、同题型/主辅考点、具体依据、确定性/冲突、是否仅实验、验证结果 |

先用旁挂manifest连接现有v2数据，后续确需改变schema或数据库时另行增量迁移，不修改已应用的001–005。缺答案的整理草稿与正式导入对象分离，不能用假A答案填充来通过现有导入器。

拟定处理状态：`registered → best_ocr_complete → proofreading_complete → json_validated → machine_content_passed`。异常按页/题保留待处理状态。用户的`batch_confirmed/returned`独立记录；人工点击不能把前置阶段未完成的内容伪装成机器校对完成。

## 6. 系统内审核与AI关联页面

- 系统主流程展示机器已完成的校对结果、完成覆盖、修订摘要和异常数量。默认机器尽可能完成质量合格内容的本机入库与“机器校对通过”记录；用户界面只需整批确认或退回，保留逐题查看作为可选操作，不再要求用户逐题劳动或重复确认来源。
- 自动入库仍走服务端质量检查、权限、版本和审计，不能直接在数据库中批量改approved以代替OCR/校对。只有实际质量门通过才可记录机器通过；此自动化尚未实现。
- “已审核题库”将展示可用内容并区分机器校对与用户确认，不凭一个按钮认定OCR质量。现有页面目前依据bank_content_reviews，本轮不改变既有审核记录；实现时需兼容既有状态和明确标记旧记录的证明范围。
- “AI关联维护”保持独立页面。先整理内容库，再统一规范主辅考点、同义名，做2023/2024/2025跨年份匹配。匹配和核对由助手承担，用户不手动建立关联。
- 试验候选与正式关联分开；对齐题型、主考点和材料，记录依据及不确定项；未验证候选不用于正式推荐/按考点组卷。内容通过不自动发布关联，内容退回应停止相应推荐。

## 7. 2023、2024最小测试及后续全题库批处理

**先跑通最小闭环，再批处理所有题库。** 最小范围为2023、2024各选一份完整原始试卷，按实际原卷确定题量，包含其配套资料中现有的答案、解析、听力原文；缺失资料登记，不把它们称为已经处理。两个年份不要混存为一份卷。

最小测试必须提供：

1. 包含原本无文字层和已有文字层的强制重识别样例；验证Best配置真实生效，全部页面重新识别。
2. 全部已OCR文档完整校对一轮；试卷/材料范围不只抽查。原图、文字、JSON可追溯，修复题号、填空、重音、跨页和水印问题。
3. 程序核对原题号、选项数、答案引用、Part、材料题组、重复版本和新旧覆盖。阅读完整，真实题量不足如实显示。
4. 校对JSON可重复生成和检查；重复导入不产生重复题，失败可定位并从安全边界恢复，不覆盖原稿。
5. 机器校对/人工批次确认可区分；当前普通用户权限、答案保密、历史记录和基础存档不受影响。
6. 在独立AI关联页面/实验数据中进行跨年份匹配，给出具体题目和依据，区分可确认、弱候选及不匹配，不以合成年份替代真实测试。
7. 形成最小测试报告，说明完成量、未解决量、修订例子和后续批处理适用范围。用户已表达测试完成后交助手批处理的意图，不为日常逐卷工作重复请求批准；若关键门槛未满足，先修复，不以扩大批次掩盖失败。

批处理按年份/卷别独立批次，保留每批manifest、状态和复核证据，可暂停恢复并重复执行。资源并发与错误隔离以最小测试结果决定；不新增无必要的线上AI密钥、任务队列或向量数据库。正式线上发布仍另按现行备份、恢复和迁移流程执行；全题库本机处理不代表自动上线。

## 8. 与现有系统的关系及实现缺口

| 能力 | 当前实际状态 | 1.6需要做的事 |
| --- | --- | --- |
| SQLite考试/成绩/报告 | Stage1已实现并部署，冻结快照 | 保留全部基础数据和版本 |
| 候选JSON导入/校验/去重 | 已实现 | 接入OCR与校对manifest，核对机器质量门 |
| 内容审核、已审核题库、独立关联页 | 已实现本机版 | 增加机器执行者/校对覆盖/批次确认，保持两套状态独立 |
| 强制Best重识别 | 未实现统一可验证流程 | 全页渲染后识别，避免跳过已有OCR；验证配置与语言模型 |
| 全量校对和修订JSON | 先前只有局部整理/抽查证据 | 建立覆盖、修订与待核实记录，先完成23/24全闭环 |
| 2023 OCR实验 | 已证明NAPS2能产出20页可搜索PDF | 未证明Best、未完成全量校对；不算1.6验收完成 |
| 2025现有候选与存档 | 已验收答案及候选基础 | 旧内容不自动标成新流程合格；后续处理生成新版本，不覆盖旧档 |
| 已审核内容接入完整真题/组卷 | 尚未接通 | 阶段3 D23–D24落实；创建后冻结题目/答案/顺序，D29读取当次版本 |

本次设计更新不改产品运行代码、数据库或部署，也不替任何批次创建机器校对完成记录。
