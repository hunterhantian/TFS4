# 同题型、同知识点匹配体验

2026-10-28，Stage2本机功能体验，未部署云端，不代表正式检索质量门通过。

## 体验方式

启动`node scripts/stage2-matching-review.mjs`，打开 `http://127.0.0.1:4180/`。账号和随机密码仅保存在本机`.local/stage2-matching-demo/匹配体验账号.txt`，不提交Git。登录后选择首页“同题型同知识点匹配体验”。

首次启动会从当前v4库一致备份生成独立体验副本；之后不覆盖或自动同步副本。演示账号有副本管理员权限，但匹配体验页面本身仅发GET读取请求，不提供审核/发布按钮。试选答案只在页面中显示，不创建考试、判分或写个人历史。若在其他管理员页面修改体验副本，不会同步源库或线上。

1. 点击“先看一组能匹配的题”，并排阅读两道题，试选答案。
2. 查看四个程序条件：当前可检索、题型相同、规范主知识点相同、排除自身/重复原题。
3. 查看两题的主知识点定义、归类依据及易混边界。部分已知示例有高亮的题干线索和单独标注的AI教学解释。
4. 展开实际分析引用、复核记录和MD原文页码。实际引用是整句时照实展示，不冒充已经逐词定位关键证据；教学解释与保存的分析证据分开。
5. 点击“再看一组不匹配的题”：两题虽然同为语法选择，但主知识点不同，因此严格匹配不返回。
6. 可在两个下拉框中任意选择当前可检索题比较，或点击出发题的其他关联结果切换。

## 原理与当前限制

第一步由AI分析题目的实际规则，提出规范主知识点并保存依据、边界和独立轮次复核。第二步由程序在有效发布组合中查找相同typeId及相同primaryId的其他题，排除自身和重复原题。匹配条件成立后，再按同考法、本人未做、跨年份等排序；排序位置不是匹配置信度。

新页面只展示有效发布组合绑定的分析，不取同题最新一条尚未发布的分析冒充实际匹配依据。目录修订失效或分类不再核验有效时，对应题不进入体验列表；比较接口也拒绝它。跨题型迁移、易混辨析仍是原有独立能力，不混入本页默认严格匹配。

例如默认正例是2012第45题与2013第51题：都要求按被替代事物的性数选主有代词。前者还受s’occuper de支配，后者是直接宾语位置；知识点相同不意味着句子、答案字符串或介词必须相同。页面教学说明是AI解释，不是来源官方解析，也不改变参考答案采纳状态。

当前快照为38道可检索题；三卷新增351项内容审核通过的候选没有因此自动分类发布。部分题没有其他严格匹配题，应显示无结果，不能凑数。参考答案仍可能仅mapped，页面展示来源候选且不计分。不同复核runId不代表不同模型，当前没有完整跨模型或全题库精度认证。若知识点分类本身错误，程序即使精确按标签查找也会匹配错误，因此D19标注质量和D21独立检索验收仍需继续。
