## 一、协作与版本管理

采用**分阶段交付、分阶段体验验收**。

每个阶段按以下流程推进：

**确定阶段范围 → 开发与自测 → 提交体验版 → 用户体验批改 → 修正与回归 → 验收通过 → 发布。**

| 参与方 | 负责事项 |
| --- | --- |
| 助手 | 代码、数据整理、测试、部署脚本、文档、问题定位和修复 |
| 用户 | 提供官方资料、审核知识点关联、体验批改、阶段验收 |
| 外部 GPT | 根据官方解析辅助分类；根据错题学习包设计学习材料 |

任务状态统一为：**待开始／开发中／待用户验收／需修改／已完成／受阻**。没有验证证据的任务不标记完成。

开发使用阶段分支；体验版验收通过后合并到 `main`，发布时打版本标签。线上版本不随每次代码提交自动变化。

执行时每项任务应记录：任务编号、状态、关联提交或测试证据、遗留问题；勾选框仅在任务完成后勾选。
