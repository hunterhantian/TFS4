## 一、推荐方案

采用 **现有轻量前端＋Node.js＋Fastify＋SQLite＋Nginx**。

第一版面向个人和少量朋友，预计同时作答不超过 20 人。资料由助手整理导入，AI 分类在外部完成，适合从单台服务器开始。

| 部分 | 选择 | 对项目的作用 |
| --- | --- | --- |
| 用户前端 | 原生 HTML、CSS、JavaScript 模块 | 复用现有界面，手机打开时加载较少内容 |
| 后端 | Node.js 24 LTS＋Fastify 5 | 处理登录、保存、组卷、判分和推荐 |
| 数据库 | SQLite＋better-sqlite3 | 保存题库、账号、作答历史和知识点关系 |
| 音频、图片 | 服务器文件目录 | 数据库只保存文件路径和来源 |
| 网站入口 | 现有 Nginx | 提供网页、音频和 HTTPS，转发接口请求 |
| 后台运行 | systemd | 开机启动、异常重启和日志管理 |

本机已安装 Node.js 24，开发与服务器运行环境统一使用受支持的 LTS 版本，并维护安全更新。[Node.js 版本说明](https://nodejs.org/en/about/previous-releases)

这里的“轻量”指部署组件少、运行依赖少、更新容易，不追求把所有代码塞进一个文件。

## 二、代码与数据怎样组织

### 2.1 前端：保留界面，拆分职责

沿用现有视觉设计，将当前集中在一起的逻辑拆为首页、考试、报告、错题本、能力追踪和接口请求模块。

- 普通用户使用首页、考试页、考试记录、错题本和能力追踪五类主要页面；首页提供能力摘要和入口。
- 能力趋势使用原生 SVG 绘制折线图和分项条形图，配套可读数值、时间范围筛选和触控详情，不增加前端构建流程。
- 管理员使用独立的简洁审核页面，不引入整套大型后台模板。
- 页面使用浏览器原生模块，不增加前端打包流程。
- 断网时暂存未同步作答，并明确显示“尚未同步”；恢复后重新提交。
- 服务器保存最终记录，本地缓存只帮助恢复，不作为云端存档的替代品。

### 2.2 后端：一个程序，按业务拆分

同一个后端承担账号、题库、考试、报告、错题、训练安排、能力统计及审核功能。通过同域名的 `/api/` 接口供页面访问。

采用 Fastify 提供路由、输入校验、错误处理和日志能力，减少自行编写基础设施。[官方文档](https://fastify.dev/docs/latest/)

| 接口组 | 职责 |
| --- | --- |
| 账号 | 登录、退出、当前用户；管理员创建和重置账号 |
| 题库 | 可用年份、题型、材料及管理员审核 |
| 考试 | 创建试卷、保存进度、暂停、恢复、提交 |
| 报告 | 历史列表、标题修改、逐题与分项结果 |
| 错题 | 错误时间线、筛选、训练、学习包导出 |
| 训练安排 | 将已完成同考点训练加入待练列表、查询关联训练及创建后续 Mini 混合测试 |
| 能力分析 | 单次及时间范围统计、综合与四项趋势、样本依据和提分指引 |

普通用户读取任何记录时，后端都检查归属；未交卷接口不返回答案或解析。

### 2.3 数据库：用普通关系表表达知识点关联

核心数据分为：

- 用户与登录会话。
- 试卷来源、材料、题目及版本。
- 知识点、同义名称、题目与知识点的关联及审核依据。
- 测试实例、固定题目顺序与作答记录。
- 每次错误事件、训练来源。
- 同考点训练完成时间、待练安排、后续 Mini 实例与训练来源的关联。
- 能力统计规则版本、计算参数和参与记录范围；基础作答保留正式分项、时间、题目版本及重复作答标识。

能力视图从可追溯的历史记录计算，不能用一个不断覆盖的“当前能力分”替代原始记录。少量用户阶段按查询计算，不引入独立分析数据库。

**同题型、同知识点推荐通过数据库查询实现。** 首版不需要向量数据库，也不需要每次推荐都调用 AI。

SQLite 支持此类单机应用，但同一数据库同时只有一个写入者。采用短事务、批量保存和 WAL 模式，以实际并发测试验收；未来出现持续写入排队或需要多台应用服务器时，再评估迁移数据库。[SQLite 适用场景](https://www.sqlite.org/whentouse.html)

数据库访问统一放在独立模块中，采用明确的 SQL 和版本化迁移文件，暂不引入大型 ORM。[better-sqlite3 项目](https://github.com/WiseLibs/better-sqlite3)

## 三、重要产品功能的实现方式

### 3.1 导入与知识点审核

固定采用这条链路：

**用户提供资料 → 助手与外部 AI 整理 → 生成统一格式的 JSON 和材料文件 → 导入候选区 → 管理员在后台批量审核 → 发布关联。**

导入内容包括原题、官方答案、解析、材料、主辅考点，以及解析依据。导入时检查题号对应、材料引用和重复来源，错误批次不直接进入正式题库。

网站不保存 AI 密钥，不承担扫描件识别和模型任务调度。官方资料与结构化数据分别保留，方便纠错和重新导入。

### 3.2 保存、计时与跨设备继续

- 作答立即进入本地待同步缓存；依据2026-10-26阶段1体验意见，服务器每5分钟同步一次考试状态（含答案、信心、位置和时间），不因单题选择或换页立即发送。
- 离开考试页面、暂停和交卷时主动保存；无法确认成功时明确提示。
- 服务器检查记录版本，避免旧设备覆盖新进度。
- 每份考试使用有期限的设备占用状态；换设备需要明确接管。
- 交卷由后端执行一次完整事务，重复请求返回同一份结果。
- 页面隐藏时暂停计时和音频，按已确认产品规则恢复。

### 3.3 错题与报告

交卷时保存题目和答案版本、作答、信心度、用时及结果，再建立错误事件。

后续重练不会覆盖以前的错误。推荐查询优先匹配已审核的同题型、同主考点题目，再按是否做过、来源年份排序。学习包先支持 **Markdown 导出**，方便交给外部 GPT。

报告接口继续采用统一的题目、材料与分项关系，为能力分析提供来源；训练记录显式标记原题重练、定向新题和延后混合验证，避免混淆普通测试与重复训练。

### 3.4 登录

采用管理员创建账号、用户名密码登录。密码使用带独立盐的安全哈希保存；登录状态使用服务器会话和 HttpOnly Cookie，不将登录令牌放进浏览器本地存储。

正式开放账号使用前配置 HTTPS，并加入登录频率限制、会话过期和管理员权限检查。

### 3.5 同考点训练后的延后混合测试

- 复用同考点训练、待练列表及已有 Mini 组卷能力，形成“错题学习 → 同考点新题 → 隔几天后的混合测试”。不新增测试模式。
- 同考点训练完成后，由用户主动加入待练列表；保存所属用户、来源训练、完成时间和后续测试关联。显示“建议隔几天再测”，不计算强制到期时间，不发送自动提醒。
- 创建关联 Mini 时，仍执行词汇 5 题、语法 10 题、完整阅读 5 题和不含听力的规则。混入来源训练已审核考点的不同题目与其他考点题目，固定本次顺序。
- 训练来源题目不冒充新题；组卷同时遵守完整材料、同卷不重复和题量约束。无法同时满足关联考点、其他考点及固定结构时，明确返回题库不足，不静默退化为无关联 Mini。
- 作答接口不返回逐题知识点标签、目标题标记或能揭示对应考点的训练来源详情；这些关联仅在提交后的报告中展示。组卷与统计使用的来源信息仍由后端保存。
- 听力来源不通过 Mini 验证，不将听力混入或转换成其他分项；混合来源中仅使用非听力部分，并明确提示覆盖范围。
- 待练列表与关联报告执行用户归属检查。通过常规请求完成全部流程，不引入定时队列、间隔算法或通知服务。

### 3.6 能力分析与追踪

- 在现有后端增加统计模块，通过 SQLite 查询聚合，提供每次测试及时间范围内听力、词汇、语法、阅读表现，综合趋势及提分依据。
- 接口接收时间范围，返回规则版本、分项与综合数据点、样本数量、来源记录和数据不足或陈旧说明；支持 7/30/90 天及自定义范围。
- 统计口径由 D39 审阅确认后实施，集中版本化管理。有效题量、时间加权、最低样本、重复题、定向训练、未答及待复核题的处理不得分散写死在图表中。
- 原始考试成绩不因能力算法变化而修改。历史对比按同一规则版本计算，响应提供参与范围，规则变化明确标注。
- Mini 不生成新的听力数据；缺失分项不补零，四项不齐不生成误导性综合值。综合使用确认后的固定分项权重，不因近期专项频率改变权重。
- 信心度、耗时用于解释和练习指引；未经另外确认，不参与能力分计算。未校准不同试卷难度时明确标为测试表现统计，不生成官方分数预测。
- 提分指引使用可解释规则结合分项表现、已确认分值占比和错题分布，返回对应专项、错题筛选或相关题训练入口；权重未知或题库不足均明确提示。
- 原题重练、同考点训练、延后混合测试保留来源区别；混合验证不被默认为独立随机评估，是否纳入及如何加权由 D39 统一确认。
- 所有统计仅返回当前用户的数据；首页摘要和详情页复用同一统计模块。

## 四、部署、更新与备份

继续使用现有腾讯云 Ubuntu 服务器：

```text
浏览器
  ↓ HTTPS
Nginx
  ├─ 网页、样式、音频
  └─ /api/ → 一个 Node.js 进程 → SQLite
```

- 代码、数据库、材料和备份分目录存放。
- 数据库、用户记录和凭据不进入 GitHub，也不位于可公开下载的网站目录。
- 后端仅监听本机地址，由 Nginx 转发。
- 音频由 Nginx 提供范围请求支持，方便 Safari 播放和拖动进度。
- 发布流程为：检查代码 → 一致性备份 → 更新应用 → 执行数据库迁移 → 验证 → 切换版本。
- 每次发布前下载一份数据库备份到本机；服务器每日保留最近 14 天备份。音频和原始资料单独备份。
- 使用数据库备份接口生成一致副本，不直接复制正在写入的数据库文件。
- 初期通过 SSH 运行统一发布脚本，暂不增加 Docker、Redis、独立任务队列或持续部署平台。

域名和证书在正式上线账号功能前落实；这是部署前置条件，不影响本地开发。

## 五、验证与实施顺序

按已确认产品规划逐阶段交付，技术基础只建设一次：

1. **基础服务与可靠保存**：账号、数据库、自动保存、暂停恢复和云端报告。
2. **题库关联**：统一导入格式、官方解析、知识点与批量审核。
3. **短测试**：专项和 Mini 组卷、音频、手机端。
4. **错题循环**：错误历史、相关题训练、学习包导出、用户主动安排的延后 Mini 混合测试。
5. **能力分析与追踪**：统计口径审阅、综合与四项趋势、样本追溯、可解释提分指引。

正式分项、题目版本、测试时间、首次及重复作答、训练来源和关联关系从数据基础阶段保留，不等到能力图表阶段再补采。

每阶段必须覆盖以下相关场景：

- 重复交卷不重复建档，服务重启不丢记录。
- 断网恢复、旧设备回传和跨设备接管不会静默覆盖答案。
- 两个账号的数据隔离。
- Mini 题量准确、材料题组完整、未审核关联不参与推荐。
- 错误历史保留，报告依据固定版本。
- 延后混合测试无考点提示，提交后可追溯训练来源；新题、混合考点、Mini 题量及材料约束不被破坏。
- 待练安排没有强制固定间隔或自动提醒，听力不进入 Mini，样本不足明确提示。
- 单次和区间能力统计可复算追溯，覆盖不同题量、重复训练、缺失听力、陈旧数据及规则版本变化。
- 综合与分项图表支持手机触控，提分建议可进入对应训练；账号隔离适用于图表、待练安排和关联报告。
- 20 名用户同时保存和提交的模拟验证。
- iPhone Safari 作答、暂停、音频播放与恢复。
- 从备份恢复到独立环境，并核对题目和考试记录。

首版保持“原生前端＋单个 Node.js 服务＋SQLite”的结构，覆盖已确认产品规划，并控制部署、维护和后续修改的负担。


## 2026-10-26自动计时与管理员报告补充

前端以单调时钟自动记录选答间隔，暂存pendingTiming并随五分钟进度同步，暂停/提交在事务中结算；报告保留timingMode，旧历史不重算。存档标题用冻结考试主题及服务器提交时间自动生成，时区Asia/Shanghai。管理员通过独立受角色检查的只读接口查看所有已提交存档；普通接口归属检查和进行中考试隔离不放宽。细则见阶段1数据接口约定及交付测试报告最新修订。


## 信息配色实施（1.3）

保持原生前端，使用集中CSS变量与语义类实现鲜明信息配色。存档列表接口返回结构化theme/mode/customTitle，前端以submittedAt拆出北京时间日期与时刻，完成度按answered/total展示，不解析标题或改写历史存档。遵循界面信息配色规范，后续页面复用同类颜色；测试模式、部署结构及判分规则保持既有基准。
