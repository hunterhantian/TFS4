# 阶段2既有交付与1.6验收要求

2026-10-27。**既有页面/接口已实现并自测；依据用户最新设计，Stage2重新进入开发中。** 新的强制Best OCR、全量校对修订JSON及机器批处理尚未实现，不再描述为只等用户在后台点审核。

## 当前可体验内容

本机：http://127.0.0.1:4175/ 。启动命令`node scripts/stage2-review.mjs`。凭据在Git忽略的`.local/stage2/验收账号说明.txt`，数据库为`.local/stage2/app.sqlite`，不与Stage1本机副本或云库同步。

| 内容 | 当前实际实现 |
| --- | --- |
| 导入 | v2统一JSON校验、候选/无效批次、错误报告、内容与来源版本去重 |
| 内容审核 | 单题/批量通过与退回，无必填说明，不依赖分类、解析、来源人工确认 |
| 已审核题库 | 年份/题型组合筛选、分页、详情、版本去重与退回移出 |
| AI关联维护 | 独立页面，外部分类导入、依据确认、关联核对、审核/发布及审计 |
| 报告关联 | 基于冻结题目的已发布同题型/主考点查询，材料完整，账号历史隔离 |
| 版本保护 | 已发布关联只读、增量迁移、历史考试/报告不重算 |

这些能力是新流程的基础，不是上游OCR和全量校对已经完成的证明。当前系统仍主要以人工内容审核状态显示“已审核”；机器处理证据、执行者类型、质量门和可选整批确认需要继续开发。

## 新的验收要求

执行规范见[Stage2机器主导题库生产流程](Stage2机器主导题库生产流程.md)，开发顺序见[阶段2实施计划](阶段2实施计划.md)。

1. 所有来源文档强制最佳质量OCR，包括已有文字层；全页重新识别可验证，记录模式、模型、语言、DPI与哈希。原始文件保留，混合年份先拆分。
2. 每份OCR文档均由助手全量对照原页校对一轮，修复并保存结构化JSON、覆盖范围、修订前后和依据；不仅抽查，不将原始OCR包进JSON即称完成。
3. 程序质量门验证题号/顺序、选项、填空、Part、材料、答案来源、去重与版本。机器通过有处理证据和AI执行者，人工批次确认独立、可选。
4. 先2023/2024各一份完整原卷和现有配套资料跑通最小闭环，实测已有OCR也重做，修复水印、S1/51、重音、选项粘连和下划线丢失等已发现问题。
5. 单独进行真实跨年关联试验并给出依据与不确定项；实验候选不直接用于推荐。用户不手工建立关联。
6. 最小测试门槛通过后，助手按同一流程批处理全题库，保留逐批状态、断点恢复、错误隔离、幂等和质量摘要。用户只需可选整批确认和最终体验验收。

## 数据和范围保护

现有2025候选/答案/报告不能因文档升级自动改成“Best OCR且全量校对完成”。后续复处理建立新版本，保留用户已经做的内容审核记录；2025指定参考答案61=A、62=B以及全部历史快照不重算。缺答案/解析、出处不明与题面识别错误分开记录，AI建议不冒充官方依据。

此前1.6设计修订轮未修改应用、数据库、运行服务或部署。Stage1线上仍保留，生产发布继续要求当前云库一致备份、下载、独立恢复与迁移兼容检查。阶段3 D23–D24的已审核题库接入完整真题/组卷尚未实现，D29需读取当次冻结版本；没有提前实现专项/Mini、错题训练、能力评分或音频刷新位置恢复。


2026-10-27工作边界补充：本轮2023/2024只处理真题、答案和解析，含卷面听力选择题；用户已独立完成的听力原文、翻译及音频均不处理、不OCR、不转码、不改写。先前处理中已产生的范围外临时OCR结果不纳入JSON或数据库，原始文件保留。
