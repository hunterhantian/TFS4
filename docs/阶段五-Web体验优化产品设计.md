# 阶段五：Web 体验优化产品设计

状态：本地实现与文案精简已完成，真实手机验收待进行
基础：阶段四已合并的功能与现有界面
定位：改善使用体验，不以增加功能为主要目标。

## 一、目标

让用户更容易找到下一步，在练习过程中保持专注，并能放心地暂停、继续和查看结果。参考 macOS 的简洁、清晰层级、稳定导航、克制的视觉效果和自然反馈，形成适合软柿子的 Web 体验；保留现有深蓝与暖橙的品牌方向，不复制系统界面或暗示与 Apple 有官方关系。

## 二、设计原则

1. **一个页面一个主要任务**：主操作明确，次要说明与低频操作按需展开。
2. **位置稳定**：返回、导航、保存状态和考试关键操作容易找到，避免布局随交互突变。
3. **轻而清晰**：统一间距、字体、卡片与按钮层级，避免装饰遮挡内容或降低可读性。
4. **及时反馈**：加载、保存、筛选、空状态和失败都显示明确结果；保留必要的确认和错误恢复。
5. **答题优先**：题目、原文、音频、进度和暂停入口始终服务作答，不泄露答案。
6. **跨设备可用**：桌面和手机功能一致，布局分别适配，支持键盘操作、焦点可见、合理触控面积和减少动态效果。

## 三、重点页面

### 主页与导航

把主页组织成清晰的学习工作台，突出“开始测试”和“软柿子变硬”；考试记录、真题题库、知识树及其他已有入口保持易找。统一页面标题、返回路径与当前位置，减少不必要的跳转。

### 考试与训练

优先展示题目、材料、剩余或已用时间、进度与必要操作；题目导航和听力音频方便访问。保存、暂停和恢复状态明确；切换题组时保持位置与上下文，避免意外丢失作答。长篇材料与不同题型在手机上仍可舒适阅读。

### 考试报告

参考现有 Stage1 报告中清晰的概要、分项与题目明细层级，优先呈现结果和下一步，再按需展开题目、原文与解析。候选关联、待核对和未作答应有清楚的状态说明。

### 软柿子变硬及分页面

- **知识树诊断**：清楚区分真题年份范围和用户作答时间范围；保留逐层浏览、重点提示和训练入口。
- **我的错题**：突出选择时间、查看错题与重做；解释题目去重和单次 50 题上限。
- **知识点掌握程度**：围绕第二层知识树展示所选时间与最近 14 天正确率，同时展示作答次数和关联状态。
- **最近作答**：信息简洁、时间和来源清楚，可与考试档案建立可理解的回看路径。

### 真题题库与知识树

保留已有搜索、筛选和展开方式；提升长文本层次、操作状态与加载反馈。用户可在题库、知识点和学习诊断之间理解上下文，不改变现有数据口径。

## 四、视觉与交互规范方向

- **色彩**：深色背景与分层表面，暖橙突出主要操作和需要关注的结果，淡紫作辅助强调；为文字、边框、禁用和错误状态检查对比度。
- **排版**：建立一致的标题、正文、辅助文字、数字和间距层级；长题面保持舒适行长和行距。
- **组件**：统一卡片、主次按钮、输入框、日期选择、标签、弹窗、空状态和加载状态；同一含义使用一致的样式。
- **反馈与动效**：点击与切换给出及时反馈，动效短且有用途；遵循系统减少动态效果的设置。
- **适配**：桌面利用宽度展示并列信息，手机优先单列与可触达操作；真实设备验证原生日期、音频和输入体验。

以上为设计方向；具体颜色、尺寸与交互细节通过样板页和实际测试确定。

## 五、实施顺序

1. 逐页体验并建立问题清单，覆盖桌面、手机、键盘导航及加载、空数据、错误状态。
2. 梳理导航、信息层级和通用组件，形成视觉规范及移动端规则。
3. 选择具有代表性的页面制作样板，确认设计方向后再推广到其他页面。
4. 依次优化主页与导航、考试与训练、报告、软柿子变硬及题库知识树。
5. 用隔离测试账号执行关键用户流程，检查布局、操作、数据保存、辅助功能和性能；记录问题并回归。

## 六、验收关注点

- 新用户能够找到开始测试、继续草稿和查看报告的入口。
- 操作反馈及时，页面切换与长内容阅读顺畅；保存或网络异常时状态清楚，现有作答与档案得到保护。
- 知识树范围、统计口径、未测试和待核验状态可理解；主要功能不因视觉调整丢失。
- 桌面与手机宽度下没有明显遮挡或横向溢出，支持键盘操作和减少动态效果；真实设备验收单独记录。
- 不更改既有判分规则、题库内容、账号权限和历史报告口径，除非后续明确提出。

## 七、范围边界

阶段五主要处理 Web UI 和体验。若审视中发现影响流程的功能缺陷，可另行记录并修复；新增业务功能、调整判分或线上部署需结合后续具体指令安排。
