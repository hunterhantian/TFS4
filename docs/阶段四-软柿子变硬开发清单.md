# 阶段四开发清单：软柿子变硬

状态：待开发与验收
日期：2026-11-03
产品设计：[知识点诊断与训练](阶段四-知识点诊断与训练产品设计.md)
GitHub 开发基线：`stage-4-learning`；具体提交及线上状态以实施时核验结果为准。

## 目标与范围

在首页以第一位、最显眼的配色呈现“软柿子变硬”入口；进入后，通过个人作答记录识别需要关注的知识点，查看依据，进行针对性训练，并回看训练和作答变化。所有界面与既有配色排版体系协调，醒目且保持可读性。

本阶段不设计或展示能力值、掌握度数值、综合能力分、预测分及其计算与历史曲线。知识点状态、题数、作答结果、时间和覆盖范围用于解释事实，不是能力评分。所有任务均未开始；现有编号 D31—D38、D45—D47 和 S4-K01—K05 保留与原清单的关联。

## 5. 弱点侦查与选题（D35、S4-K04）

- [ ] S4-25 制定可解释的关注排序，考虑不同题目上的错误、跨时间反复、近期表现、证据质量及题库可用性；支持查看触发依据。
- [ ] S4-26 分开“建议加强”和“证据不足、建议先测试”；单题多知识点时区分主要和其他关联，不把关联假设当作确定病因。
- [ ] S4-27 支持用户手动选择知识点进行针对性训练，并根据历史记录发起弱点强化。
- [ ] S4-28 从全部可用年份和题型中选择符合条件的题目，优先未做和不同年份；不可用、来源不足、题目不足时说明，不靠重复或不可靠内容凑数。
- [ ] S4-29 完形、阅读保留解题所需完整原文及题组；作答中不暴露答案。实际题量、预计时间和暂停机制在开始前说明。

## 执行顺序与验收结果

先完成基线盘点和事件证据，再开发首页与诊断、错题和训练，最后实现待练混合检验、全链路测试与用户验收。任务依赖和具体题量、诊断门槛须在对应开发前确定。每完成一批记录真实证据；没有完成验收前保持未勾选。
