# 软柿子：题库改造与腾讯云部署方案

记录日期：2026-10-24

本文保存后续改造方向，作为分阶段实施的依据。本文描述的是规划，不代表功能已经实现。

## 1. 目标与现状

目标是将当前固定的 2025 年法语专四试卷升级为可按规则抽题的题库，同时继续使用现有简洁的深色答题界面，支持 iOS Safari 与桌面浏览器。

当前完整考试系统位于仓库的 `dist/` 目录，包含试题、阅读材料、信心度选择、计时和本机考试存档。题目及工作答案从 `dist/exam-data.js` 读取，判分在浏览器完成，答题进度和记录保存在浏览器本地。

仓库根目录还保留原有听力原型。部署当前完整考试系统时，应使用 `dist/` 作为网站目录。

## 2. 总体结构

```text
手机 Safari / 桌面浏览器
            │ HTTPS
            ▼
          Nginx
          ├── 网页与静态资源
          └── /api/ → 后端程序 → MySQL
```

页面和答题交互继续沿用，主要增加后端接口和数据库。浏览器通过接口读取题目、创建试卷和提交作答，后端负责抽题与判分，数据库保存题库和试卷关系。

题库与云端考试存档分开实施：第一阶段可以仅将题目迁入数据库，继续使用本机存档；需要跨设备共享考试记录时，再加入身份识别和云端存档。

| 部分 | 当前方式 | 改造方向 |
| --- | --- | --- |
| 题目来源 | 读取静态 JavaScript 数据 | 调用后端接口 |
| 组卷 | 固定 2025 年真题 | 根据年份、题型、数量等规则抽题 |
| 判分 | 浏览器读取答案并判分 | 后端判分，提交后返回结果 |
| 考试记录 | 浏览器本地存档 | 后续可保存到数据库 |
| 页面 | 显示固定试卷 | 显示本次生成的试卷 |

未交卷的题目接口不返回正确答案；数据库连接信息只保存在服务器后端。

## 3. 数据设计

以下为逻辑结构，具体表名与字段在实施时确定。

| 数据 | 主要内容 |
| --- | --- |
| 材料 | 材料 ID、类型、阅读文章、听力原文、音频地址 |
| 题目 | 独立题目 ID、年份、原题号、题型、题干、所属材料、版本 |
| 选项与答案 | 所属题目、选项内容、正确答案、答案复核状态 |
| 试卷 | 试卷 ID、来源或抽题规则、创建时间 |
| 试卷题目 | 所属试卷、题目版本、排列顺序 |
| 考试记录 | 所属试卷、提交时间、总用时、成绩；云端存档阶段再关联使用者 |
| 逐题记录 | 选择结果、信心度、题目用时、判分结果 |

### 3.1 关联材料与题组

阅读、听力和完形填空存在上下文关系，不能把所有题目当作彼此独立的记录随意抽取。一篇材料对应多道题时，默认以材料及关联题组为单位抽取，组内保持原有顺序。

自动分页也应继续参考材料和题组关系，尽量保持每页 5–15 题，避免把文章与对应题目拆开。

### 3.2 唯一编号与原始来源

不同年份都会出现“第 1 题”，因此数据库使用独立 ID；年份、原题号与原试卷来源另行保留，方便追溯。

### 3.3 版本与历史报告

创建试卷时固定题目和答案版本。后续修订题干或答案，不应悄悄改变已经完成的考试报告。可通过不可变版本记录或试卷快照实现。

2025 年第 55、62、100 题的工作答案保留“待复核”状态，并在报告中明确显示。

### 3.4 用时与信心度

继续保存“肯定、犹豫、猜测”和逐题耗时。实施时明确耗时统计口径及切换题目、暂停、刷新、恢复考试时的处理方式，保持各端一致。

纸质答题卡等导入记录没有提供的信心度和耗时，应保存为缺失值，报告显示“未记录”，不能用猜测值或零秒替代。

## 4. 后端接口职责

最少需要支持以下操作，具体 URL 在实施时确定：

1. 查询可用年份、题型与题目范围。
2. 读取指定真题试卷。
3. 按规则抽题并创建试卷，返回固定的题目顺序。
4. 提交本次作答，由后端根据固定答案版本判分。
5. 云端存档阶段再增加记录保存与报告读取。

抽题结果在创建试卷后固定，刷新页面不重新抽题。抽题条件不足时返回明确说明，避免静默重复题目或减少题数。

## 5. 云端环境

第一阶段建议在现有腾讯云服务器上部署全部服务。

| 软件 | 用途 |
| --- | --- |
| Ubuntu 24.04 LTS | 服务器系统 |
| Nginx | 静态网页、HTTPS、后端反向代理 |
| Node.js LTS | 运行后端接口；实施时选择仍受支持的版本 |
| MySQL 8.0 | 题库、试卷和考试记录；实施时核对支持周期与可用版本 |
| systemd | 后端开机启动和异常重启 |

个人或少量朋友使用时，2 核 4GB 可作为初步配置参考，实际是否升级根据现有实例规格与运行负载决定。当前阶段无需增加 Redis、容器集群或负载均衡。

## 6. 腾讯云配置

现有实例：

- 实例名称：OpenClaw(龙虾)-EDuX
- 实例 ID：lhins-qzpetjux
- 地域：广州七区
- 公网 IPv4：193.112.151.236

### 6.1 第一阶段：单台服务器

1. 使用 Ubuntu 系统；重装前备份仍需保留的数据。
2. Nginx 从 `/var/www/tfs4` 提供当前 `dist/` 内容。
3. 后端仅监听本机地址，例如 `127.0.0.1:3000`。
4. Nginx 将同域名下的 `/api/` 请求转发给后端。
5. MySQL 仅供本机后端连接，不开放公网访问。
6. 腾讯云防火墙开放网站 TCP 80/443，SSH 使用 TCP 22；后端 3000 与数据库 3306 不需要开放公网访问。
7. 后端由 systemd 管理，密钥和数据库密码通过服务器配置提供，不提交到 Git。
8. 数据库定时备份，并将副本保存到服务器之外；上线前验证恢复流程。
9. 正式访问地址确定后配置域名和 HTTPS。浏览器存档按访问来源隔离，从 localhost、IP 或 HTTP 切换到新域名或 HTTPS 时，不会自动迁移已有存档。

服务器重装会清空系统盘，公网 IP 保持不变。参见[腾讯云重装系统说明](https://cloud.tencent.com/document/product/1207/44576)与[实例防火墙说明](https://cloud.tencent.cn/document/product/1207/44577)。

### 6.2 后续：迁移到托管数据库

希望减少数据库维护工作或需要扩容时，再将 MySQL 从应用服务器迁到托管数据库。应用通过配置更换连接地址，页面无需因数据库迁移而重做。

- 轻量数据库：同账号、同地域的轻量应用服务器可通过内网连接，参见[官方连接说明](https://cloud.tencent.com/document/product/1207/59868)。
- 云数据库 MySQL：轻量服务器与其默认不直接内网互通，通常需要配置云联网，不能仅凭同在广州判断网络可达。参见[通过云联网访问云数据库](https://cloud.tencent.com/document/product/236/88904/)。

数据库选型、套餐、软件支持周期和网络规则在实际实施时重新核对腾讯云文档。

## 7. 分阶段实施顺序

### 阶段一：迁移现有真题数据

将 2025 年题目、材料、选项和工作答案导入数据库，保留来源、原题号、材料关系和待复核标记。确认导入前后题目与答案对应一致。

### 阶段二：接入后端

现有页面改为通过接口读取固定的 2025 年真题。后端负责判分。现有本机进度与存档仍可继续使用，并处理旧记录与新题目 ID 的对应关系。

### 阶段三：实现抽题组卷

加入抽题规则，按材料与题组关系创建固定试卷，保留每份试卷的题目版本和顺序。现有答题交互继续用于新试卷。

### 阶段四：按实际需要加入云端存档

需要跨设备共享时，再确定使用者身份识别方案，将考试进度、信心度、耗时和报告保存到云端，并为已有本地记录制定迁移方式。

## 8. 实施前应明确的事项

- 当前服务器实际 CPU、内存、磁盘和已有服务占用。
- 第一阶段是否仅自己使用，是否需要跨设备记录。
- 抽题按独立题目还是完整题组计数，以及各题型的数量规则。
- 题库修订后历史成绩是否需要重新计算；默认保留原报告。
- 正式域名与 HTTPS 配置，以及已有本地存档的迁移范围。

以上事项在对应阶段确定，无需为当前静态版本部署提前购买额外云服务。
